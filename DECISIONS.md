# Architecture Decision Records (ADRs) & Governance Log

## Record 001: Static Next.js App Router Export vs Dynamic Server
- **Status:** Accepted
- **Context:** BECOMING requires a zero-cost, zero-backend, privacy-first deployment model. The app must be fully deployable as a static bundle (`output: 'export'`) to GitHub Pages, Cloudflare Pages, or static Vercel preview without requiring serverless functions, Node servers, or databases.
- **Decision:** Use Next.js 14/15 App Router configured with `output: 'export'`. All routing, locale switching, and reflection flows are executed client-side. Images and assets are unoptimized static assets (`images: { unoptimized: true }`).
- **Consequences:** Eliminates ongoing server operational costs, server-side data leaks, and server vulnerability attack surfaces. Precludes server-rendered dynamic database lookups, which aligns with zero-cost and privacy-by-design requirements.

## Record 002: Client-Only In-Memory & Local Storage Strategy
- **Status:** Accepted
- **Context:** Reflections and journal notes must stay on the user's device. Users need control over whether their session is ephemeral or remembered on their personal device, with clear shared-device cautions.
- **Decision:** Implement a dual-tier client storage model with an explicit toggle:
  1. *Session / In-Memory Mode (Default):* State is kept strictly in React memory or `sessionStorage`, automatically cleared upon tab closure.
  2. *Local Persistence Mode (Opt-In):* Uses `localStorage` with explicit UI disclaimers regarding unencrypted shared-device risks.
  3. *Data Sovereignty Controls:* A persistent "Export Data (JSON/TXT)" button and "Wipe All Data" button are exposed prominently in navigation and settings.
- **Consequences:** Zero personal reflection data is transmitted over the wire or stored in cloud databases. Users on shared computers are protected by default ephemeral mode.

## Record 003: Multilingual Framework & RTL Logical Properties
- **Status:** Accepted
- **Context:** The system must support five languages: English (`en`), Arabic (`ar`), French (`fr`), Spanish (`es`), and Italian (`it`). Arabic is Right-to-Left (RTL).
- **Decision:** 
  1. Maintain a typed, comprehensive localization dictionary for all 5 languages without external translation network requests.
  2. Dynamically bind `dir="rtl"` or `dir="ltr"` and `lang` attribute to the document root upon locale selection.
  3. Use Tailwind CSS logical properties exclusively (`ps-`, `pe-`, `ms-`, `me-`, `start-`, `end-`, `text-start`, `text-end`) to ensure bidirectional symmetry without duplicated CSS styles.
  4. Language switching preserves the current session state without reload or data loss.
- **Consequences:** Flawless visual mirroring for Arabic while maintaining maintainable, clean layout code.

## Record 004: Purely Deterministic Reflection Engine & Explicit Fallback
- **Status:** Accepted
- **Context:** Users must never be misled into believing they are conversing with an autonomous AI companion. Cloud LLMs also introduce latency, financial costs, and privacy exposure.
- **Decision:** 
  1. Brand the conversational mode as **"Guided Reflection Preview"**.
  2. Implement an explicit state machine: `Express → Explore → Confirm → Choose → Reflect`.
  3. Prompts, mirrors, draft insights, and micro-steps adhere strictly to deterministic scripted trees defined in the project dossier.
  4. Implement an explicit fallback notice: if a user types unstructured text, the engine acknowledges the thoughts, offers gentle grounding, and provides options to proceed or adjust without pretending to have performed deep semantic parsing.
- **Consequences:** Transparent user expectations, zero API costs, zero hallucination of clinical diagnosis, and absolute privacy.

## Record 006: Non-Clinical Boundary & Crisis Protocol
- **Status:** Accepted
- **Context:** Personal reflection tools can occasionally be accessed by individuals experiencing severe distress.
- **Decision:**
  1. The app displays a clear non-clinical banner at all times.
  2. A dedicated safety boundary / crisis resource modal is directly accessible from the header at any point.
  3. In addition to a keyword-triggered safety boundary, the user is never diagnosed or offered fabricated referrals.
- **Consequences:** Protects users from misconstruing the tool as emergency therapy.
